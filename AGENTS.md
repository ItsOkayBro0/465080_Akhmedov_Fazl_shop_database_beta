# Инструкции для агента

- Работай с одной проблемой за раз и читай только файлы, которые к ней относятся.
  Не открывай `bun.lock`, `node_modules/` и `db/seed.sql`.
- Не меняй `public/`: интерфейс считается корректным.
- Схему меняй только новыми файлами в `db/migrations/`. Не редактируй уже
  применённые миграции.
- В базе выполняй только `SELECT` и `EXPLAIN ANALYZE`. Миграции применяет
  приложение после того, как студент их проверит.
- Утверждения о скорости подтверждай `EXPLAIN ANALYZE` на данных магазина, а не
  догадками.
- Правила целостности проверяй в базе, а не только в коде. Внутри транзакций не
  делай сетевых вызовов.
- Внутри `sql.begin(async (transaction) => …)` выполняй все запросы через
  `transaction`, а не через `sql`: иначе они идут мимо транзакции.
- Код ошибки PostgreSQL (SQLSTATE, например `23505`) в Bun лежит в
  `error.errno`, а не в `error.code`.
- Делай точечные изменения: без несвязанных рефакторингов и новых зависимостей.
- Для исправленного дефекта добавляй регрессионный тест, который падает на
  исходном коде. Не удаляй и не ослабляй существующие тесты.
- Тесты, линтер и `bun run race` запускает студент. Назови нужную команду и жди
  результата, сам запускай только по просьбе студента.
